# Sol 定位与最终审校范围修复

日期：2026-10-16。用户明确 Sol 用于高质量、高成本的争议裁决和多轮未解决难题，不承担大批量常规审校。

## 规则变更

- 全文独立审校及严格程序验收保持；正文后的 `quality-report --kind final` 仅选择审校明确遗留的 `issues`。
- 数字、否定、条件、变量、术语例外、长句、历史修改不自动升级 Sol；不再给 Sol 生成普通抽样、同源多译组或角色口吻组。
- 已修正并通过独立复查的记录不因曾经改动而再次进入 Sol。试译的代表性样本及 Sol 文体验收保持。
- 普通修复仍按现有最多6轮、相同条目两次术语回退的规则自动升级新 Sol 子代理；不让主对话逐条复查已通过正文。
- 结束时没有遗留争议也没有已确认问题的，通过 `sol-round-finish` 完成程序闭环，模型检查数为0；保留审校来源、证据和导出门槛，不补造 Sol 的逐项通过结论。

## 已有大范围轮的保全迁移

新的 `sol_scope_policy=disputes_only_v1` 纳入 Sol 轮版本校验。旧输入不能继续写入新轮；下一次 `quality-report` 归档旧轮并生成新范围。原报告、实际通过/语境结论、已发现问题不删除。

旧轮 `repair` 结论按实际受影响 ID 保存为 `carried_findings`，不再次要求 Sol 阅读。争议结论齐备后，`sol-round-finish` 将它们与新发现问题统一交付定向修复；只有持久化任务已接管的 ID 才从遗留责任表移除。锁定等无法派修的问题继续保留，不能通过 approve/export 绕过。
