# 翻译流程协议一致性复查

日期：2026-10-16。范围：game-translate 规范、实际 prompt、直接 submit、批次暂存与提交、试译/正文审校校验、修复输入及最终质量闭环。本轮仅修改共享流程、规范和合成测试，不运行游戏翻译、不改项目运行数据库或在途任务。

## 新发现并修复的七类问题

| 问题 | 原因与影响 | 修复与验证 |
|---|---|---|
| 试译仍漏写证据限制 | 上次修正正文审校提示，但 pilot_review 仍统一允许 not_applicable，且未明示修改摘录相等要求；校验器对试译却执行同样限制 | 补齐批总结与逐条检查的三项必查规则、摘录相等规则；已有例外须详细核对，不能用精简 pass 隐藏；提示词对照回归 |
| 直接提交与批次交接的试译例外继承不同 | 直接 submit 的继承分支未包含 pilot_translate/pilot_review；批次路径却会继承，导致相同输出走不同入口可能丢失例外或通过条件不同 | 两个试译阶段加入同一继承入口；以合成项目对照两条完整路径，确认遗漏 exceptions 时仍保留原例外并进行详细审校 |
| 逐 ID 试译总结在批次路径丢失 | validate_body_row/直接 submit 支持 review_summaries，但批次暂存只保存 review_summary；相同 JSON 经批次交接可能丢证据并被当作缺少完整 checks | 批次按每个 ID 优先保存 review_summaries[id]，与直接提交一致；重复分段输出也比较总结，禁止证据被静默覆盖 |
| 术语例外被无条件忽略大小写合并 | 继承与撤销用 casefold 键，即使冻结表存在 Guard/guard 两个不同源键也可能被覆盖或一起删除 | 继承/撤销使用冻结 src 原样值；匹配层既有唯一 ASCII 归一化保留。明确拒绝同时撤销又返回同一例外，防止撤销后静默加回 |
| 进入修复后游戏背景丢失 | 新审校修复包将 game_background 写为空，渲染修复输入又省略背景，与“各阶段使用同一背景”的规范不一致 | 新修复任务保留已配置背景；旧修复包渲染时补充当前已验证运行背景，不改变原任务哈希或数据；完整输入仍受预算及拆包检查 |
| 纯空白原文的摘录无法通过 | 空译文判断使用 source.strip()，摘录校验却用 source 的原始真值；纯空白文本无法提供非空白摘录，也不能用空摘录 | 摘录校验按相同的空白定义判断；允许纯空白源文使用空摘录，实际换行和控制符仍受结构校验 |
| 非文本值可能冒充审校理由 | 部分路径用 str(value).strip() 判断“非空”，导致 null/数字/对象等可能被当作有效语义 reason、issues 理由或术语审校总结；例外撤销理由也有同类问题 | 改为非空字符串检查；补 null/数字/布尔/对象/列表及相互矛盾的例外撤销回归。翻译疑点提示同时明确 issues 的对象数组结构 |

## 本轮确认的有意差异

- 正文草稿及独立审校候选先保存、整轮严格验收；试译即时严格验收。这是既定质量反馈策略，不把“候选已保存”当作“语义已通过”。
- 试译默认150条、最多12次执行；旧项目显式保存的预算和已用次数保留，不能因工具升级重置为新默认。
- 正文后 Sol 只裁决明确遗留争议或处理升级难题；无遗留问题时零条模型审查，由程序完成质量闭环，仍要求全量独立审校和导出验收。
- 大小写不敏感的术语匹配，可在唯一确定时规范例外源键；这不等于允许在继承层将不同冻结源键合并。
- 实机检查中 fonts/layout 必须实测 pass；其他不在范围的类别可说明 not_applicable，未验证或失败不能发布。

## 防止再次漂移

`test_contract_pipeline.py` 对照真实的直接提交和批次提交入口，检查继承例外及逐 ID 总结是否一致；另测旧修复背景补充不改任务。`test_review_contract.py` 覆盖空白原文、试译与正文提示约束、非文本理由拒绝。`test_workflow_repair_policy.py` 覆盖大小写不同的冻结键和撤销冲突。质量规范、批次协议及整轮审校参考已同步更新。

验证结果：56项协议/试译/批次/整轮审校回归通过；最后补充的17项契约与修复策略测试、两条提交入口的交叉验证及2项端到端/空术语表回归亦通过。模块编译及 diff 空白检查通过。均使用项目现有 AINiee Python 虚拟环境，无真实模型调用。

限制：程序证据契约一致不等于语义判断正确；本次是静态协议核对与合成数据回归，不构成对游戏全文的重新语义验收，也不宣称覆盖所有可能分支。
